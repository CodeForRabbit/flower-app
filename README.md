# 公会鲜花查询

这是一个纯静态网页，用来查询公会成员拥有的鲜花，也可以按鲜花反查拥有者。页面不需要后端，适合直接发布到 GitHub Pages。

## 文件说明

- `index.html`：网页入口。
- `assets/guild-flower-data.js`：生成后的网页数据。
- `scripts/generate-data.mjs`：从名单和图册生成网页数据。
- `公会成员.txt` 或 `空白文本.txt`：成员与鲜花名单，生成器会优先读取 `公会成员.txt`。
- `鲜花图册/`：鲜花图片目录，图片文件名需要和花名一致。

## 更新数据

平时只需要维护根目录下的 `空白文本.txt`，修改后直接提交并 push。网页发布到 GitHub Pages 后，会优先读取最新的 `空白文本.txt` 来显示成员和鲜花关系。

只有新增、删除或重命名鲜花图片时，才需要重新生成图片索引：

```bash
node scripts/generate-data.mjs
```

运行后会更新 `assets/guild-flower-data.js`。输出里会显示成员数、鲜花数、图片数、缺图数和重复填写数。这个文件也作为本地双击打开页面时的兜底数据。

如果名单里有花名没有匹配到图片，首页会显示缺图提醒；对应鲜花仍然会出现在“按成员”和“按鲜花”视图里，并显示“缺图”占位。

## 本地查看

可以直接双击打开 `index.html`。如果浏览器对本地文件限制较多，也可以运行：

```bash
python3 -m http.server 8080
```

然后访问 `http://127.0.0.1:8080/`。

## 移动端使用

页面按手机浏览优先设计：

- 搜索框可以同时搜索成员名和花名。
- “按成员”适合快速看某个人有什么花。
- “按鲜花”适合反查某朵花谁有。
- “导出图片”会生成一张手机宽度的 PNG 长图，包含所有成员和所拥有鲜花，适合保存或发到群里。

## 发布到 GitHub Pages

把整个文件夹推送到 GitHub 仓库，在仓库设置里开启 Pages，发布根目录即可。需要包含这些内容：

- `index.html`
- `assets/guild-flower-data.js`
- `鲜花图册/`
- 可选：`公会成员.txt`、`scripts/`、`tests/`

## 检查

运行测试：

```bash
node --test tests/*.test.mjs
```
